El origen

Por qué construí esto

Trabajé en un entorno donde los repartidores llegaban cada mañana a una pila de albaranes en papel. Tenían que ordenarlos manualmente, decidir por dónde empezar, y al final del día devolver los papeles firmados — que a menudo se perdían. La oficina no sabía qué se había entregado hasta que el repartidor volvía.

Esa desconexión entre el repartidor y la oficina me pareció un problema técnicamente interesante de resolver: ¿cómo digitalizar ese flujo con herramientas accesibles, sin infraestructura cara, y que además demostrara criterio de ingeniería?

Kavana Route AI es mi respuesta. Un MVP que cubre el ciclo completo: OCR de albaranes → optimización de ruta → firma digital → Torre de Control con métricas de coste real.

Arquitectura backend real

API REST con Express, 20+ endpoints, middlewares JWT, carga de archivos, generación de PDF, OCR, geocodificación. Separación clara de responsabilidades en servicios.

Base de datos dual

Nominatim gratuito pero impreciso. 8 formatos de query por dirección + bounding box de Valencia. ~80% acierto. ADR →

Decisiones técnicas

Criterio aplicado, no solo código

Más allá de las tecnologías, aquí hay decisiones de arquitectura que responden a restricciones reales: coste cero para MVP, disponibilidad sin conexión, simplicidad operativa.

🧮 2-opt en vez de IA para rutas

La IA parecía la opción obvia, pero los modelos gratuitos daban resultados inconsistentes y tardaban 30s. El algoritmo 2-opt es determinista, milisegundos, 0€ de coste y no necesita internet. ADR →

🗺️ Nominatim con validación geográfica

Geocodificar direciones españolas gratis no es trivial. Implementé 8 formatos de query por dirección + bounding box de Valencia para filtrar resultados de otras ciudades. ADR →

🗄️ BD dual: PostgreSQL y JSON

El sistema funciona con PostgreSQL en producción o con un archivo JSON en desarrollo — sin cambiar una línea de código de negocio. Misma interfaz de queries, dos implementaciones. Ideal para desarrollar sin infraestructura.

📐 5 ADRs documentados

Cada decisión importante tiene su Architecture Decision Record: contexto, alternativas evaluadas, consecuencias. Ver ADRs →

🚀 CI/CD en dos plataformas

GitHub Actions build los frontends y los despliega a GitHub Pages. El backend Node vive en Render. Despliegue automático con cada push a main. ADR →

📱 PWA + APK nativo

La app del repartidor funciona como Progressive Web App (instalable sin Play Store) y como APK generado con Capacitor para Android. Offline-first: funciona sin conexión.
